# Embeddable signing

Embed the signing flow directly in your application so recipients can sign documents without leaving your product. This creates a seamless, white-label signing experience.

## Signing URL pattern

The signing interface is available at:

`https://app.firma.dev/signing/{signing_request_user_id}`

## URL parameters

The signing URL accepts optional query parameters to customize the experience:

| Parameter | Type | Range | Default | Description |
|-----------|------|-------|---------|-------------|
| `lang` | string | `en`, `es`, `it`, `pt`, `fr`, `de`, `el`, `ru`, `pl`, `cs`, `sv`, `nl`, `ro`, `nb`, `ca` | Browser language | Override UI language |
| `zoom` | float | `0.25`–`3.0` | fit-to-width | Initial zoom level (`1.0` = 100% natural size) |

Example with both parameters:

```text
https://app.firma.dev/signing/{signing_request_user_id}?lang=fr&zoom=1.0
```

Without `zoom`, the signing view automatically fits the PDF to the container width. On wide screens this can produce 150–200% zoom. Set `zoom=1.0` for natural reading size, or a lower value like `zoom=0.75` for a more compact view.

## Basic iframe embed

```html
<iframe 
  src="https://app.firma.dev/signing/{signing_request_user_id}" 
  style="width:100%;height:900px;border:0;" 
  allow="camera;microphone;clipboard-write"
  title="Document Signing"
></iframe>
```

### Required iframe permissions

- `camera` - For identity verification (if enabled)
- `microphone` - For video verification (if enabled)
- `clipboard-write` - For copying/pasting content

## Getting the signing URL

The `signing_request_user_id` is returned when you fetch signing request users via the API.

### Example: Get recipient signing URLs

```js
const response = await fetch(
  `https://api.firma.dev/functions/v1/signing-request-api/signing-requests/${signingRequestId}/users`,
  {
    headers: {
      'Authorization': `${API_KEY}`
    }
  }
)

const users = await response.json()

// Each user has their own signing URL
users.forEach(user => {
  const signingUrl = `https://app.firma.dev/signing/${user.id}`
  console.log(`${user.email}: ${signingUrl}`)
})
```

## Complete implementation example

### React component

```jsx
import { useState, useEffect } from 'react'

function SigningView({ signingRequestId, recipientEmail }) {
  const [signingUrl, setSigningUrl] = useState(null)
  const [loading, setLoading] = useState(true)
  const [error, setError] = useState(null)
  
  useEffect(() => {
    async function loadSigningUrl() {
      try {
        // Fetch signing request users from your backend
        const response = await fetch(
          `/api/signing-requests/${signingRequestId}/users`,
          { credentials: 'include' }
        )
        
        if (!response.ok) {
          throw new Error('Failed to load signing users')
        }
        
        const users = await response.json()
        
        // Find user by email
        const user = users.find(
          u => u.email === recipientEmail
        )
        
        if (!user) {
          throw new Error('User not found')
        }
        
        const url = `https://app.firma.dev/signing/${user.id}`
        setSigningUrl(url)
        setLoading(false)
      } catch (err) {
        setError(err.message)
        setLoading(false)
      }
    }
    
    loadSigningUrl()
  }, [signingRequestId, recipientEmail])
  
  if (loading) return <div>Loading signing interface...</div>
  if (error) return <div>Error: {error}</div>
  
  return (
    <iframe
      src={signingUrl}
      style={{
        width: '100%',
        height: '900px',
        border: 0
      }}
      allow="camera;microphone;clipboard-write"
      title="Sign Document"
    />
  )
}
```

### Server-side endpoint (Node.js)

```js
import express from 'express'
import fetch from 'node-fetch'

const app = express()
const API_KEY = process.env.FIRMA_API_KEY

app.get('/api/signing-requests/:id/users', async (req, res) => {
  try {
    const response = await fetch(
      `https://api.firma.dev/functions/v1/signing-request-api/signing-requests/${req.params.id}/users`,
      {
        headers: {
          'Authorization': `${API_KEY}`
        }
      }
    )
    
    if (!response.ok) {
      const error = await response.text()
      return res.status(response.status).json({ error })
    }
    
    const users = await response.json()
    res.json(users)
  } catch (error) {
    console.error('Failed to fetch signing users:', error)
    res.status(500).json({ error: 'Internal server error' })
  }
})

app.listen(3000)
```

## postMessage events

The signing iframe emits postMessage events for tracking signing progress:

```js
window.addEventListener('message', (event) => {
  // Validate origin
  if (event.origin !== 'https://app.firma.dev') return
  
  const data = event.data
  
  switch (data.type) {
    case 'signing.loaded':
      console.log('Signing loaded:', data.totalFields)
      break
    case 'signing.started':
      console.log('User started signing')
      break
    case 'signing.completed':
      console.log('Document signed successfully')
      // Redirect or show success message
      break
    case 'signing.declined':
      console.log('User declined to sign')
      break
    case 'signing.error':
      console.error('Signing error:', data.code, data.error)
      break
  }
})
```

| Event | When | Payload (besides `type`, `timestamp`, `source: 'firma-signing'`) |
|---|---|---|
| `signing.loaded` | The document has loaded and the signer has at least one field | `signingUserId`, `signerEmail`, `totalFields` |
| `signing.started` | The signer fills the first field | `signingUserId` |
| `signing.completed` | The signer finished | `signingUserId` |
| `signing.declined` | The signer declined | `signingUserId`, `reason` |
| `signing.error` | Something failed (see codes below) | `signingUserId`, `error` (localized message), `code` |

| `code` | Meaning |
|---|---|
| `LOAD_FAILED` | The page could not load the signing data after retrying (connection failure, timeout, server error). The signer sees a "Try again" screen. |
| `NOT_SENT` | The signing request has not been sent yet. The signer sees the "Try again" screen. |
| `LINK_INVALID` | The signing link does not match an existing recipient or request. The signer sees the "Invalid Signing Link" page. |
| `SEAL_PAUSED` | An organization seal earlier in the signing order is paused, so it is not this signer's turn yet. |
| `SAVE_FAILED` | Saving or finishing failed. |
| `NETWORK_ERROR` | Saving or finishing failed while the browser was offline. |
| `DECLINE_NOT_ALLOWED` | Declining is turned off for this request. |
| `DECLINE_FAILED` | Declining failed. |

A load failure (`LOAD_FAILED`, `NOT_SENT`, `LINK_INVALID`, `SEAL_PAUSED`) is posted once and can arrive without any earlier `signing.loaded`. The page retries a failed load automatically for up to about 30 seconds before it posts `LOAD_FAILED`. If your page needs its own fallback, treat a missing `signing.loaded` (origin `https://app.firma.dev`, `source` `firma-signing`) about 30 seconds after the iframe's `load` event as a failed load, and offer the signer a retry that reloads the iframe. Note that `signing.loaded` is only sent when the signer has at least one field.

A second embedded tab or device that opens or reloads the signing link after the signer has finished receives no `signing.completed` or `signing.error` message: that tab shows the already-signed screen. A tab that was already open before the signer finished can still send `signing.completed` (on Finish) or `signing.error` (on Decline). The `signing_request.recipient.signed` and `signing_request.completed` webhooks remain the host's durable signals.

## Security best practices

<Warning>
  **Never expose API keys in frontend code.** Always fetch signing user IDs through a secure backend endpoint.
</Warning>

### ✅ Do's

- ✅ Fetch signing user IDs through your backend
- ✅ Validate postMessage origins (`https://app.firma.dev`)
- ✅ Use HTTPS for all API requests
- ✅ Monitor signing events via webhooks (60 req/min)

### ❌ Don'ts

- ❌ Don't expose API keys in client code
- ❌ Don't trust postMessage data without origin validation

## Webhook integration

Use webhooks to track signing events in real-time instead of polling:

```js
// Webhook handler
app.post('/webhooks/firma', async (req, res) => {
  const event = req.body
  
  switch (event.type) {
    case 'signing_request.viewed':
      await notifyUser(event.data.signing_request.id, 'viewed')
      break
    case 'signing_request.recipient.signed':
      await notifyUser(event.data.signing_request.id, 'signed')
      break
    case 'signing_request.completed':
      await markComplete(event.data.signing_request.id)
      break
  }
  
  res.json({ received: true })
})
```

## Troubleshooting

If the signing page is blank or black, ask the signer to reload it, try a private window or another supported browser, disable content blockers for the page, and confirm that hardware acceleration is enabled.

### Iframe not loading

**Possible causes**:

- The signing link's recipient ID does not exist or was deleted: the page shows "Invalid Signing Link" and posts `signing.error` with `LINK_INVALID`.
- The signer's connection failed or timed out: the page retries, then shows a "Try again" screen and posts `LOAD_FAILED`.
- The signing request has not been sent yet: `NOT_SENT`.
- A paused organization seal is earlier in the signing order: `SEAL_PAUSED`.

Completed, cancelled, declined and expired requests show their own pages, not an error; check the request's state with [`GET /signing-requests/{id}`](/api-reference/signing-requests/get-signing-request).

### postMessage events not received

**Possible causes**:

- Origin validation blocking messages
- Event listener not attached before iframe loads

**Solution**:

- Check origin is exactly `https://app.firma.dev`
- Attach listener before creating iframe

### 403 Forbidden when fetching signing request

**Possible causes**:

- User doesn't have access to the signing request
- API key lacks required permissions

**Solution**: Verify authorization logic and API key permissions
